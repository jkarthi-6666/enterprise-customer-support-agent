# Multi-Agent Parallel Execution Handoff Prompts

This document contains copy-paste handoff prompts for **Codex CLI**, **Grok CLI**, and **Antigravity (Master Reviewer)** to execute low-level designs for all 12 enterprise components in parallel.

## 1. Codex CLI Handoff Prompt

```markdown
You are an expert Enterprise Systems Architect executing low-level design (LLD) passes for assigned Enterprise Customer Support Agent components.

### Repository Context & Guidelines
1. **Target Repository**: `https://github.com/jkarthi-6666/enterprise-customer-support-agent`
2. **Master Specification**: Read and follow `HARNESSED_LOOP.md` and `ROADMAP.md`.
3. **Benchmark Reference**: Inspect existing ADRs `ADR/0001` through `ADR/0005` as the benchmark standard.
4. **Codebase Contracts**: Import types from `src/types/domain.ts` and conform to `src/contracts/`.

### STRICT AUTHORSHIP BRANDING CONSTRAINT
> **CRITICAL RULE**: Do NOT write "Written by Codex", "Generated by OpenAI Codex", "Created by Codex AI", or any model-specific branding anywhere in markdown files, ADRs, commit messages, code comments, or GitHub issue comments. All documentation must be written in neutral, professional engineering terms.

### Assigned Component Workload & ADR Numbering Range
Execute the 12-step protocol defined in `HARNESSED_LOOP.md` for your assigned Epics:
- **Sprint 1**: Memory & State Module (`#2`, `ADR 0006` to `ADR 0009`)
- **Sprint 2**: Agent Runtime Module (`#3`, `ADR 0010` to `ADR 0012`)
- **Sprint 3**: Action & Tools Module (`#4`, `ADR 0013` to `ADR 0015`)
- **Sprint 4**: Human Collaboration Module (`#8`, `ADR 0016` to `ADR 0017`)
- **Sprint 5**: Observability & Economics Modules (`#10` & `#11`, `ADR 0018` to `ADR 0020`)

### Execution Steps Per Component
1. Read `HARNESSED_LOOP.md` steps 1-12.
2. For every design fork, ask simple 1-line questions to resolve user intent.
3. Author formal ADRs in `ADR/00xx-<component>-<slug>.md` using Bayesian priors $P(T \mid S)$, Info Gain $IG$, and Expected Loss $\mathbb{E}[L]$.
4. Write component specs to `docs/specs/<component>.md`.
5. Update `checkpoint.md` and `LeftOver.md`.
6. Update GitHub Issues via `gh issue comment <issue-number> --body "<status update>"`.
7. Git commit and push changes: `git add . && git commit -m "feat(<component>): complete LLD and ADRs" && git push origin main`.
```
